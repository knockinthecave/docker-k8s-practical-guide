# 이미지 공유하기: push & pull

> 이미지를 가진 사람은 누구나 그 이미지로 컨테이너를 실행할 수 있다. 이미지를 **레지스트리**에 올리고(`push`) 내려받는(`pull`) 방식으로 팀원이나 배포 서버와 공유한다.

## 도커를 쓰는 이점

- **로컬 종속성을 설치할 필요가 없다.** Node, Python 같은 런타임을 로컬 시스템에 전역으로 설치하지 않아도 된다. 모두 이미지를 통해 사용한다.
- 도구를 설치하거나 제거하지 않고도 **여러 버전이 공존**할 수 있다.
- 이미지와 컨테이너를 **공유**할 수 있다. (배포 서버, 프로젝트 팀원 등)

## 이미지를 공유하는 2가지 방법

| 방법 | 받는 사람이 할 일 |
|------|------------------|
| **Dockerfile을 포함한 프로젝트 공유** | Dockerfile을 받아 **직접 빌드**해야 한다. |
| **빌드된 이미지 공유** | 이미지를 **다운로드만 하면** 바로 컨테이너를 실행할 수 있다. 추가 코드나 주변 폴더가 필요 없다. |

- 일반적으로 쓰는 방식은 **빌드된 이미지를 공유**하는 것이다.
- 공유된 이미지는 `FROM`으로 가져다 쓰는 것과 같은 방식이다. 내가 만든 Dockerfile 없이도 이미지를 공유할 수 있다.

## 이미지를 올릴 수 있는 곳

| 위치 | 설명 |
|------|------|
| **Docker Hub** | 공식 도커 이미지 레지스트리 |
| **프라이빗 레지스트리** | 여러 공급자가 있어 골라 쓴다. (예: AWS ECR) |

이미지를 레지스트리에 푸시하면 다른 사람이 그 이미지를 받아 사용할 수 있다.

## 명령어

```bash
docker push <IMAGE NAME>
docker pull <IMAGE NAME>
```

| 명령 | 설명 |
|------|------|
| `docker push` | 이미지를 레지스트리에 올린다. |
| `docker pull` | 레지스트리에서 이미지를 내려받는다. |

## 이미지 푸시하기

### 1. 이미지 이름 맞추기

푸시하려면 이미지 이름이 **`주소(prefix)/레포지토리이름:태그`** 형식이어야 한다.

```bash
docker push 주소/레포이름:tagname
```

- 로컬에서 **prefix와 레포지토리 이름**을 붙여 이미지를 빌드하면 된다.
- 이미 만들어 둔 이미지는 **리태깅**으로 이름을 바꿔 재사용할 수 있다.

```bash
docker tag OLD_NAME NEW_NAME
```

### 2. 로그인

내가 만든 레포지토리에 푸시하려면 **권한**이 필요하다. `docker login`으로 연결을 설정한다.

```bash
docker login
```

### 3. 푸시

```bash
docker push 주소/레포이름:tagname
```

- 레이어 단위로 **필요한 추가분만 푸시**하므로 대역폭과 공간이 절약된다.
- `latest` 태그는 지정하지 않으면 **자동으로 생성**된다.

> **주의:** Public으로 푸시할 때는 **보안 관련 데이터(키, 비밀번호 등)가 이미지에 포함되지 않도록** 조심한다.

## 이미지 내려받기: docker pull

```bash
docker pull <IMAGE NAME>             # latest 태그
docker pull <IMAGE NAME>:<TAG>       # 특정 태그
```

- 태그를 생략하면 기본 태그인 `latest`로 받는다. 태그를 지정해서 받을 수도 있다.
- **`pull`은 로그인 없이 가능하다.** (공개 이미지의 경우)
- Dockerfile이 아니라 **공유된 이미지**로 컨테이너를 실행하는 방식이며, 배포에도 사용된다.
- `docker pull`을 실행하면 **항상 레지스트리에서 최신 이미지**를 가져온다.

## docker run과 이미지 업데이트

`docker pull`을 먼저 하지 않고 `docker run`을 실행했을 때의 동작:

| 로컬 상태 | `docker run` 동작 |
|----------|-------------------|
| 이미지가 **없음** | 레지스트리에서 **자동으로 pull**한 뒤 실행한다. |
| 이미지가 **이미 있음** | 최신 버전이 있는지 **확인하지 않고** 로컬 이미지로 실행한다. |

- `docker run`만으로는 **최신 업데이트된 이미지를 받지 못한다.**
- 업데이트하려면 **수동으로 `docker pull`** 을 한 뒤 실행해야 한다.
- 자동으로 pull하더라도 그것이 최신 버전인지는 상관없이 받아 온다는 점을 알아 두자.
