# 이미지 살펴보기: docker image inspect

> 이미지는 **코드와 애플리케이션 환경**을 담고 있어 크기가 크다. 실행 중인 컨테이너는 그 위에 얹힌 **얇은 부가 레이어**일 뿐이다. `docker image inspect`로 이미지 내부 구성을 확인할 수 있다.

## 이미지와 컨테이너의 관계

- 컨테이너는 이미지를 기반으로 빌드되고, **같은 이미지로 실행한 컨테이너들은 이미지 내부의 코드를 공유**한다.
- 그래서 이미지 안의 코드는 **읽기 전용(잠김)** 이다. 컨테이너에서 이미지를 직접 바꿀 수 없다.
- 컨테이너에서 파일을 만들거나 수정하면, 모든 이미지 레이어 위에 추가된 **얇은 컨테이너 레이어**에만 기록된다.

```
┌───────────────────────────────┐
│ 컨테이너 레이어 (쓰기 가능)        │  ← 컨테이너마다 개별 존재
├───────────────────────────────┤
│ 이미지 레이어 (읽기 전용)          │
│ 이미지 레이어 (읽기 전용)          │  ← 같은 이미지의 컨테이너끼리 공유
│ 이미지 레이어 (읽기 전용)          │
└───────────────────────────────┘
```

## 이미지 정보 확인

```bash
docker image inspect <IMAGE ID>
```

이미지에 대한 정보가 **긴 JSON**으로 출력된다.

## 출력에서 확인할 수 있는 정보

| 항목 | 설명 |
|------|------|
| 생성 시각 | 이미지가 만들어진 시간 |
| 이미지 ID | 이미지 고유 식별자 |
| 노출 포트 | `EXPOSE`로 정의된 포트 정보 |
| 컨테이너 정보 | 이미지 빌드 시 사용된 컨테이너 관련 설정 |
| 환경 변수 | 이미지에 설정된 일부 환경 변수 |
| 기본 엔트리 포인트 | 기본으로 실행되는 명령 (`CMD`, `ENTRYPOINT`) |
| 도커 버전 / 운영체제 | 이미지를 만든 도커 버전과 OS |
| 레이어 | 이미지를 구성하는 레이어 목록 |

## 레이어 확인 시 참고

- 레이어 수는 **Dockerfile에 정의한 명령 수와 다를 수 있다.** 베이스 이미지의 레이어가 함께 포함되기 때문이다.
- 이미지를 재빌드할 때 **캐시를 이용해 효율적으로 다시 만들 수 있는 것**이 레이어가 존재하는 이유다.

## 언제 쓰는가

- 다른 소스(Docker Hub 등)에서 **가져온 이미지의 구성**을 확인할 때
- 이미지가 **생성된 이후** 내부를 살펴볼 때

> `inspect`로 레이어를 직접 들여다보는 것은 흥미롭지만 자주 쓰는 명령은 아니다. 이미지 구성이 궁금할 때 참고용으로 사용한다.
