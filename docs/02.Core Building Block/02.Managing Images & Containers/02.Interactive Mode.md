# 인터랙티브 모드 (Interactive Mode)

> 도커는 웹 서버 전용 도구가 아니다. 사용자와 **입력·출력을 주고받는 애플리케이션**도 컨테이너로 실행할 수 있고, `-i`, `-t` 옵션이 그 통로를 열어 준다.

## 도커는 웹 서버만을 위한 것이 아니다

- 지금까지는 웹 개발과 요청 처리 같은 **백그라운드 프로세스**를 주로 다뤘지만, 이는 도커의 일부일 뿐이다.
- 웹 서비스를 어떤 언어로 만들든 상관없고, Node.js나 웹 서버에 국한되지도 않는다.
- 컨테이너는 **포그라운드(전면)** 와 **백그라운드(배경)** 모두에서 실행될 수 있다.
- 사용자와 상호작용하는 앱도 컨테이너로 돌릴 수 있다. 간단한 유틸리티 애플리케이션에도 도커를 쓸 수 있다.

## 예제: 난수 생성기 (`rng.py`)

사용자가 min / max 값을 직접 입력하면 그 범위의 난수를 출력하는 파이썬 스크립트다.

```python
import random

print("Random Number Generator")

try:
    min_number = int(input("Please enter the min number: "))
    max_number = int(input("Please enter the max number: "))
except ValueError:
    print("Invalid input - shutting down...")
    raise SystemExit(1)

if max_number < min_number:
    print("Invalid input - shutting down...")
    raise SystemExit(1)

rnd_number = random.randint(min_number, max_number)
print(f"Your random number is: {rnd_number}")
```

| 입력 | 결과 |
|------|------|
| 숫자가 아닌 값 | `Invalid input - shutting down...` 출력 후 종료 |
| `max_number < min_number` | `Invalid input - shutting down...` 출력 후 종료 |
| 정상 입력 | 범위 내 난수 출력 |

`CMD`로 이 스크립트를 실행하도록 이미지를 만든다.

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY rng.py .

CMD ["python3", "rng.py"]
```

```bash
docker build -t rng-app .
docker run rng-app          # EOFError로 종료됨 (입력 수단이 없음)
```

`input()`은 표준 입력(STDIN)을 기다리는데, 기본 `docker run`은 STDIN을 열어 주지 않아 입력을 받지 못한다.

## `-i`와 `-t` 옵션

| 옵션 | 설명 |
|------|------|
| `-i` (`--interactive`) | **STDIN을 열어 둔다.** 컨테이너에 무언가를 입력할 수 있게 된다. |
| `-t` (`--tty`) | **터미널(TTY)을 할당한다.** 입력을 받고 출력을 보여 주는 터미널이 열린다. |

```bash
docker run -it rng-app
```

- 두 옵션을 함께 쓰는 `-it`가 일반적이며, 서로 충돌하지 않는다.
- 실행하면 프롬프트가 뜨고 값을 직접 입력해 결과를 확인할 수 있다.

```
Random Number Generator
Please enter the min number: 1
Please enter the max number: 10
Your random number is: 7
```

## Detached 모드에서는?

- `-d`(detached)로 실행하면 터미널과 분리되어 **입력을 주고받을 수 없다.**
- `docker attach <컨테이너>`로 붙을 수는 있지만, 이미 진행 중인 프로세스에 붙는 것이라 **한 번만 입력 가능**하다.

## 종료된 컨테이너에 다시 입력하기

종료된 컨테이너는 `docker start`로 다시 시작할 수 있다. 이때 `docker start`는 기본이 **detached 모드**이므로, 상호작용하려면 옵션을 붙여야 한다.

```bash
docker start -a -i <컨테이너 이름 또는 ID>
```

| 옵션 | 설명 |
|------|------|
| `-a` (`--attach`) | 출력(STDOUT/STDERR)에 **붙는다.** |
| `-i` (`--interactive`) | STDIN을 열어 **입력**할 수 있게 한다. |

- `-t` 없이 `-a -i`만으로도 입력과 출력이 가능하다.
- 컨테이너를 매번 새로 만들지 않고 **기존 컨테이너를 재사용**하며 입력을 반복할 수 있다.

## 정리

| 상황 | 명령 |
|------|------|
| 새 컨테이너를 만들어 상호작용 | `docker run -it <이미지>` |
| 종료된 컨테이너를 다시 시작해 상호작용 | `docker start -a -i <컨테이너>` |
| 실행 중인 컨테이너의 출력만 확인 | `docker attach <컨테이너>` |
