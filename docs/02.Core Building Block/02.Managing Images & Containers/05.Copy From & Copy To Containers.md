# 컨테이너로 파일 복사: docker cp

> 실행 중인 컨테이너에 파일을 **넣거나**, 컨테이너 안의 파일을 **꺼내고** 싶을 때 `docker cp`를 사용한다. 로컬 호스트 머신과 컨테이너 사이에서 파일을 주고받는 명령어다.

## 사용법

```bash
docker cp <복사할 항목 경로> <복사 도착지>
```

순서는 항상 **복사할 경로 → 목적지**다.

### 호스트 → 컨테이너

```bash
docker cp dummy/. kind_babbage:/test
# Successfully copied 6B (transferred 2.56kB) to kind_babbage:/test
```

| 부분 | 설명 |
|------|------|
| `dummy/.` | 복사할 항목 경로 (`dummy` 폴더 안의 내용 전체) |
| `kind_babbage:/test` | 도착지. `<컨테이너 이름>:<컨테이너 내부 경로>` |

### 컨테이너 → 호스트

경로 순서만 바꾸면 반대 방향으로 복사된다.

```bash
docker cp kind_babbage:/test ./dummy
```

## 특정 파일만 복사

폴더 전체가 아니라 대상을 구체적으로 지정하려면 `.txt` 등 **정확한 파일명**을 적는다.

```bash
docker cp dummy/test.txt kind_babbage:/test
```

## 활용 시나리오

| 상황 | 방법 |
|------|------|
| 컨테이너 안의 소스 코드가 바뀌었을 때 | 변경된 파일을 컨테이너에 복사해 넣을 수 있다. |
| 구성 파일(설정 파일)을 꼭 넣어야 할 때 | 호스트에서 컨테이너로 복사한다. |
| 컨테이너가 로그 파일을 많이 생성할 때 | 로그를 호스트로 꺼내 확인한다. 컨테이너 내부(블랙박스)를 들여다볼 수 있다. |

## 주의

- 실행 중인 컨테이너에 파일을 복사해 넣는 것은 **좋은 해결책이 아니다.**
  - 복사한 파일은 **그 컨테이너에만** 존재한다. 이미지는 바뀌지 않으므로 컨테이너를 새로 만들면 사라진다.
  - 코드 변경은 이미지를 **다시 빌드**하는 것이 정석이다.
- 복사할 수밖에 없는 경우(구성 파일 등)에만 제한적으로 사용한다.
- 반대로 **컨테이너 → 호스트** 방향(로그 추출 등)은 유용하게 쓰인다.
