# 이미지는 읽기 전용이다

> 이미지는 **빌드가 끝나면 잠기는 닫힌 템플릿**이다. 소스 코드를 수정해도 이미지는 바뀌지 않으므로, 변경 사항을 반영하려면 **이미지를 다시 빌드**해야 한다.

## 문제 상황

애플리케이션 코드를 수정한 뒤 컨테이너를 다시 시작하면 애플리케이션은 재시작된다. 하지만 **수정한 코드는 반영되지 않는다.**

```
코드 수정 ──▶ 컨테이너 재시작 ──▶ 그래도 이전 코드로 동작 ✗
```

## 왜 반영되지 않을까?

이미지가 만들어지는 방식을 이해해야 한다.

`Dockerfile`의 `COPY` 명령은 소스 코드를 `WORKDIR`에 선언한 폴더로 복사한다.

```dockerfile
WORKDIR /app
COPY main.py .      # 이 시점의 main.py를 /app에 복사
```

- `COPY`는 복사한 **그 시점의 스냅샷**을 이미지 안에 만든다.
- 이후 로컬의 소스 코드를 수정해도 **이미지 안의 코드는 그대로**다.
- 이미지는 **읽기 전용**이라 외부에서 편집하거나 업데이트할 수 없다.

```
          빌드 시점                          코드 수정 후
로컬 main.py (v1) ──COPY──▶ 이미지 /app/main.py (v1)
로컬 main.py (v2)            이미지 /app/main.py (v1)   ← 변하지 않음
```

## 해결: 이미지를 다시 빌드한다

> **매우 중요** — 코드를 변경했다면 **반드시 이미지를 새로 빌드**해야 한다.

```bash
# 1. 코드 수정
# 2. 이미지 재빌드 (새 이미지가 생성된다)
docker build .

# 3. 새 이미지로 컨테이너 실행
docker run -p 8000:8000 <새 이미지 ID>
```

- `docker build`를 다시 실행하면 **새로운 이미지**가 만들어진다.
- 기존 이미지를 고치는 것이 아니라, **변경 사항이 담긴 새 이미지를 만드는 것**이다.
- 컨테이너는 새 이미지 ID로 다시 실행해야 변경 사항이 반영된다.

## 개발 흐름

```
코드 수정 ──▶ docker build ──▶ 새 이미지 ──▶ docker run ──▶ 변경 사항 반영
```

## 정리

| 구분 | 설명 |
|------|------|
| `COPY` | 복사한 시점의 **스냅샷**을 이미지에 저장한다. |
| 이미지 | 빌드가 끝나면 **잠긴 읽기 전용 템플릿**이 된다. |
| 코드 수정 | 이미지에 자동으로 반영되지 **않는다**. |
| 반영 방법 | `docker build`로 **다시 빌드**해 새 이미지를 만든다. |

> 이미지는 빌드 후 잠겨서 완료되는 **닫힌 템플릿**이다. 이 점을 이해하는 것이 핵심이다.
