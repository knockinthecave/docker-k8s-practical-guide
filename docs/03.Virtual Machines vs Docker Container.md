# 가상 머신(VM) vs 도커 컨테이너

## 가상 머신

호스트 OS 위에 가상 머신을 만들고, 그 안에 게스트 OS(예: 리눅스)를 설치해 필요한 것을 모두 구성하는 방식이다.
환경이 캡슐화되므로 컨테이너와 비슷한 역할을 하며, 여러 대를 만들어 환경을 나눌 수도 있다.

### 장점

- 분리된 환경을 제공한다.
- 환경별 구성을 가질 수 있다.
- 안정적으로 공유하고 재현할 수 있다.

### 단점

- 가상 머신마다 OS 전체를 설치해야 해서 **메모리 등 리소스 오버헤드**가 크다.
- 매번 비슷한 것들을 반복해서 설치하므로 **디스크 공간**을 많이 차지한다.
- 여러 대를 띄우면 성능이 떨어지고 **부팅이 오래 걸린다**.
- 모든 설정을 직접 맞춰야 하고, 이를 표준적으로 기술·공유할 구성 파일이 없어 **구성과 공유, 재구축, 배포가 까다롭다**.
- 환경만이 아니라 **컴퓨터 전체를 캡슐화**해 버린다.

문제를 해결하긴 하지만 최선의 방법은 아니다.

## 도커 컨테이너

- 컨테이너도 호스트 OS 위에서 실행되지만, 가상 머신처럼 OS를 통째로 설치하지 않는다.
- OS의 **내장 컨테이너 지원**을 이용하며, 그 위에서 **도커 엔진**이 컨테이너를 실행한다.
  - 리눅스에서는 호스트 커널을 공유한다. macOS와 Windows에서는 Docker Desktop이 경량 리눅스 VM을 하나 띄우고 그 안에서 컨테이너를 실행한다.
- 가상 머신보다 훨씬 **가볍다**.
- **구성 파일(Dockerfile)** 로 환경을 정의하고 공유할 수 있으며, **이미지**를 통해 모두가 동일한 컨테이너를 시작할 수 있다.

### 장점

- 호스트 OS에 미치는 영향이 적다.
- 디스크 사용량이 최소화된다.
- 구성 파일로 공유, 재구축, 배포가 쉽다.
- 필요한 것만 캡슐화하므로 불필요한 요소가 없다.

## 비교

| 항목 | 가상 머신 | 도커 컨테이너 |
|------|-----------|---------------|
| OS | VM마다 게스트 OS 설치 | 호스트 OS 커널 공유 |
| 자원 사용 | 크다 | 작다 |
| 시작 속도 | 느리다 | 빠르다 |
| 환경 정의 | 표준 구성 파일 없음 | Dockerfile / 이미지 |
| 공유·배포 | 까다롭다 | 쉽다 |
| 캡슐화 범위 | 컴퓨터 전체 | 앱과 필요한 환경만 |

> 도커는 컨테이너를 만들고 관리하는 표준 도구일 뿐이다.
