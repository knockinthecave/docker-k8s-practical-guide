# 다중 컨테이너 환경의 어려움

> 컨테이너가 하나일 때는 `docker run` 한 줄이면 충분하다. 하지만 앱·DB·캐시처럼 **함께 동작하는 컨테이너가 여러 개**가 되면 명령어 관리 자체가 일이 된다. 도커 컴포즈가 필요한 이유를 정리한다.

## 컨테이너마다 해야 할 일이 많다

다중 컨테이너 환경을 직접 띄우려면 컨테이너마다 아래 작업을 **일일이 명령어로** 해야 한다.

| 작업 | 사용하는 명령 |
|------|---------------|
| 이미지 빌드 | `docker build` |
| 네트워크 생성 | `docker network create` |
| 볼륨 생성 / 마운트 | `docker volume create`, `-v` |
| 환경변수 주입 | `-e`, `--env-file` |
| 포트 매핑 | `-p` |
| 컨테이너 이름 지정 / 네트워크 연결 | `--name`, `--network` |
| 백엔드 컨테이너 실행 | `docker run` |
| DB 컨테이너 실행 | `docker run` |

## 예시: 컨테이너 2~3개를 띄우는 데도 명령이 길다

우리 실습(FastAPI 앱 + Redis)만 해도 이 정도다. 여기에 DB나 프론트엔드가 더해지면 명령은 더 늘어난다.

```bash
# 1. 네트워크 생성
docker network create app-net

# 2. 캐시(Redis) 컨테이너 실행
docker run -d --name cache --network app-net \
  -v redis-data:/data \
  redis:7.2-alpine

# 3. 앱 이미지 빌드
docker build -t docker-practice-image .

# 4. 앱 컨테이너 실행
docker run -d --name app --network app-net \
  -p 8000:8000 \
  -e REDIS_HOST=cache \
  docker-practice-image
```

- 명령마다 옵션(`--network`, `-v`, `-e`, `-p`)이 길게 붙는다.
- **실행 순서**(네트워크 → Redis → 앱)를 사람이 기억해야 한다.
- 컨테이너 이름, 네트워크 이름, 환경변수 값이 **서로 맞아야** 한다. 하나라도 틀리면 통신이 실패한다. (`REDIS_HOST=cache` ↔ `--name cache`)
- 종료할 때도 `docker stop`, `docker rm`, `docker network rm`을 컨테이너마다 반복해야 한다.

## 문제 정리

- 다중 컨테이너 환경은 각 컨테이너를 **서로 연결해야 할 것**(네트워크, 환경변수, 볼륨, 포트)이 너무 많다.
- 함께 동작하는 기본 컨테이너 3개를 띄우는 데에도 **상당한 수고와 시간**이 든다.
- 긴 명령을 매번 손으로 입력하면 **오타·누락 같은 실수**가 생기기 쉽고, 팀원에게 환경을 공유하기도 어렵다.

## 해결책: 도커 컴포즈

이런 어려움 때문에 도커 생태계는 **도커 컴포즈(Docker Compose)** 를 제공한다.

- 다중 컨테이너 설정을 **하나의 파일에 선언**해 두고 한 번에 실행·종료할 수 있다.
- 다중 컨테이너 설정을 **자동화**하는 데 큰 도움이 된다.
