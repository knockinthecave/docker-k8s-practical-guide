# 인수(ARG)와 환경변수(ENV)

> 이미지 빌드와 컨테이너 실행 시점에 값을 바꿔 쓸 수 있도록, 포트·앱 이름 같은 값을 하드코딩하지 않고 변수로 다루는 방법을 정리한다.

## 개요

| 구분 | 인수 (ARG) | 환경변수 (ENV) |
| --- | --- | --- |
| 값을 주는 시점 | `docker build` | `docker run` (기본값은 Dockerfile) |
| 옵션 | `--build-arg` | `--env` / `-e` / `--env-file` |
| 사용 가능한 범위 | **Dockerfile 안**, 빌드 중에만 | Dockerfile + **실행 중인 앱 코드** |
| 컨테이너 실행 후 | 값이 보이지 않음 | 값이 유지됨 |

- 둘 다 **하드코딩을 피하고** 하나의 이미지·컨테이너를 서로 다른 구성(다른 포트, 다른 버전 표기 등)으로 쓰게 해 준다.
- 예: 포트 번호를 다르게 써야 할 때, 버전을 표기할 때.

## 인수 (ARG)

Dockerfile 안에서 특정 명령에 쓸 **변수**를 선언하고, 빌드할 때 값을 바꿔 넣는다.

```dockerfile
ARG DEFAULT_PORT=8000
```

```bash
docker build -t docker-practice-image --build-arg DEFAULT_PORT=9000 .
```

- 값은 `docker build`의 `--build-arg 이름=값`으로 준다. (`--build -arg`가 아니라 `--build-arg`)
- 인수는 **Dockerfile 안, 빌드 중에만** 쓸 수 있다. 앱 코드나 `CMD`가 실행될 때는 이미 사라져서, 컨테이너에 들어가 `echo $DEFAULT_PORT`를 해도 비어 있다.

## 환경변수 (ENV)

Dockerfile의 `ENV`는 "이 환경변수가 존재한다"고 도커에 알리고 **기본값**을 정한다.

```dockerfile
ENV PORT=8000
EXPOSE $PORT
```

- 변수 이름이 `PORT`이고, 불러올 때는 `$PORT`처럼 `$`를 붙인다.
- 컨테이너가 실행되는 동안에도 유지되므로 앱 코드에서 읽을 수 있다. (이 프로젝트: `os.environ.get("APP_NAME", ...)`)

### 실행할 때 값 바꾸기 (`--env`, `-e`)

기본값이 있어도 `docker run`에서 **동적으로 덮어쓸** 수 있다. 이것이 환경변수의 이점이다.

```bash
docker run -d -p 3000:8000 --env PORT=8000 docker-practice-image
```

- `--env PORT=8000`은 컨테이너 **내부** 포트를 8000으로 쓰겠다는 뜻이다. 그래서 `-p`도 `3000:8000`처럼 내부 포트에 맞춘다.
- `-e`로 줄여 쓸 수 있고, 변수가 여러 개면 `-e`를 여러 번 쓴다.

```bash
docker run -d -p 9000:9000 -e PORT=9000 -e APP_NAME="My App" docker-practice-image
```

- 브라우저를 새로고침하면 새 포트 설정으로 연결된 것을 확인할 수 있다.

### 파일로 한꺼번에 주기 (`--env-file`)

환경변수를 파일(`.env`)에 모아 두고 `--env-file`로 읽어 올 수 있다.

```bash
# .env
PORT=9000
APP_NAME=My App
```

```bash
docker run -d -p 9000:9000 --env-file ./.env docker-practice-image
```

## 보안 주의사항

환경변수에 담는 데이터가 민감하다면 **Dockerfile에 `ENV`로 직접 넣으면 안 된다.**

- Dockerfile의 `ENV` 값은 **이미지에 포함**된다. 이미지를 가진 사람은 누구나 `docker history <이미지>`로 값을 읽을 수 있다.
- 자격 증명, 개인 키 같은 값은 반드시 피한다. 단순한 포트·앱 이름은 상관없다.
- 대신 **런타임에만** 쓰는 별도 파일을 `docker run --env-file`로 가리킨다. 그러면 값이 이미지의 일부가 되지 않는다.
- 소스 컨트롤을 쓴다면 이 `.env` 파일을 **저장소에 커밋하지 않도록** `.gitignore`에 추가한다.
- 이미지에도 섞이지 않도록 `.dockerignore`에도 `.env`를 넣는다. (이 프로젝트에는 이미 `.env`, `.env.*`가 들어 있다.)
- `ARG`로 넘긴 값도 `docker history`에 남을 수 있으므로 비밀 값 전달에는 쓰지 않는다.

## 이 프로젝트에서의 적용

```dockerfile
ARG DEFAULT_PORT=8000
ENV PORT=$DEFAULT_PORT
ENV APP_NAME="docker-practice-app"

EXPOSE $PORT

CMD ["sh", "-c", "exec uvicorn main:app --host 0.0.0.0 --port ${PORT}"]
```

- `ARG`로 빌드 시 기본 포트를 정하고, `ENV PORT`에 넘겨 실행 시 덮어쓸 수 있게 한다.
- exec 형식(`["uvicorn", ...]`)의 `CMD`는 `$PORT`를 치환하지 않는다. 그래서 `sh -c`로 감싸고, `exec`로 uvicorn이 PID 1을 유지하게 한다.
- `EXPOSE $PORT`는 **빌드 시점**의 값으로 고정된다. `docker run -e PORT=...`로 바꿔도 `EXPOSE` 표기는 그대로이며, `-p` 매핑에는 영향이 없다.
- `/health`가 `APP_NAME`을 돌려주므로 `curl localhost:9000/health`로 바뀐 값을 바로 확인할 수 있다.

CMD에서는 사용할 수 있음

CMD는 런타임 명령어이기 때문에
외적으로는 모든 명령어에서 활용 가능함

그래서 여러 이미지를 만들때 이러한 인수를 다르게 해서 빌드할 수 있음.

코드 변경없이도 다른 포트번호를 사용할 수 있음.
단지 하나의 예임

이미지를 빌드할때 코드 변경없이 유연한 방식으로 빌드할 수 있다는게 핵심임.

CMD는 ARG와 ENV 아래에 두고 써야함.
Dockerfile에 ARG, ENV도 레이어에 추가되기 때문에
변경되면 후속레이어도 다 재빌드됨.
그래서 RUN npm install 같은 종속성 설치같은 레이어 뒤에 배치하도록 하는게 좋음.

그래서 명령어 배치에도 신경을 쓰는게 좋음 (변경되면 후속레이어도 다 재빌드되니까)
