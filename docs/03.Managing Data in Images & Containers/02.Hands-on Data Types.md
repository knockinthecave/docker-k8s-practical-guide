# 실습: 세 가지 데이터 직접 확인하기

> [01.Understanding Data](./01.Understanding%20Data.md)에서 정리한 세 종류의 데이터(이미지 / 임시 / 영구)를 FastAPI 서버로 직접 확인한다.

## 실습 대상

| 데이터 종류 | 엔드포인트 | 저장 위치 (컨테이너 내부) |
|-------------|-----------|---------------------------|
| 1. 이미지 (코드 + 환경) | `GET /items` | `/app/seed/items.json` (빌드 시 `COPY`) |
| 2. 임시 데이터 | `POST·GET /notes` | `/app/tmp/notes.txt` (컨테이너 read-write 레이어) |
| 3. 영구 데이터 | `POST·GET /users` | `/app/data/users.json` (볼륨 마운트 위치) |

```dockerfile
COPY main.py .
COPY seed/ ./seed/

# 임시 데이터(tmp), 영구 데이터(data, 볼륨 마운트 위치) 디렉토리
RUN mkdir -p /app/tmp /app/data
```

이미지 빌드는 한 번만 하면 된다.

```bash
docker build -t docker-practice-image .
```

## 1. 이미지 데이터

`seed/items.json`은 빌드 시점에 이미지로 복사되어 **고정**된다.

- 호스트에서 `seed/items.json`을 고쳐도 실행 중인 컨테이너의 `GET /items`는 **그대로**다.
- 바뀐 내용을 반영하려면 이미지를 **다시 빌드**해서 컨테이너를 새로 띄워야 한다.

## 2. 임시 데이터

```bash
docker run -d -p 8000:8000 --name docker-practice-app docker-practice-image
curl -X POST localhost:8000/notes -H 'content-type: application/json' -d '{"text":"hi"}'
```

### 컨테이너 안의 파일 직접 확인

API 대신 파일을 직접 조회할 수 있다.

```bash
docker exec docker-practice-app cat /app/tmp/notes.txt
# hi

docker diff docker-practice-app
# A /app/tmp/notes.txt   ← A: 추가, C: 변경, D: 삭제
```

`docker diff`는 이미지 대비 **컨테이너 레이어에 쌓인 변경**을 보여준다. 컨테이너가 중지된 상태에서는 `exec`를 쓸 수 없으므로 `docker cp`로 꺼내서 본다.

```bash
docker cp docker-practice-app:/app/tmp/notes.txt ./notes.txt
```

### 언제 사라지는가

| 동작 | `notes.txt` |
|------|-------------|
| `docker stop` → `docker start` (재시작) | **남아 있음** (같은 컨테이너, 같은 레이어) |
| `docker rm` → 새 `docker run` | **사라짐** (레이어가 함께 삭제됨) |

```bash
docker rm -f docker-practice-app
docker run -d -p 8000:8000 --name docker-practice-app docker-practice-image
docker exec docker-practice-app cat /app/tmp/notes.txt
# cat: can't open '/app/tmp/notes.txt': No such file or directory
```

> 임시 데이터는 컨테이너가 **중지될 때가 아니라 삭제될 때** 사라진다.

## 3. 영구 데이터

`-v users-data:/app/data`로 볼륨을 붙여 실행한다.

```bash
docker rm -f docker-practice-app
docker run -d -p 8000:8000 --name docker-practice-app -v users-data:/app/data docker-practice-image
curl -X POST localhost:8000/users -H 'content-type: application/json' -d '{"name":"alice"}'
# {"name":"alice","id":1}
```

컨테이너를 **삭제**하고 같은 볼륨으로 다시 띄운다.

```bash
docker stop docker-practice-app
docker rm -f docker-practice-app
docker run -d -p 8000:8000 --name docker-practice-app -v users-data:/app/data docker-practice-image
curl localhost:8000/users
# [{"name":"alice","id":1}]   ← 남아 있음
```

`users.json`이 컨테이너 레이어가 아니라 **볼륨**에 저장되었기 때문이다. 같은 컨테이너 삭제에도 `notes.txt`는 사라지고 `users.json`은 남는다. 이 차이가 임시 데이터와 영구 데이터의 차이다.

## 볼륨 확인

```bash
docker volume ls
docker volume inspect users-data
```

- `docker volume inspect`의 `Mountpoint`는 Docker Desktop(Mac)에서 호스트가 아닌 **Docker VM 내부** 경로라 Finder로 열리지 않는다. 내용은 `docker exec ... cat /app/data/users.json`으로 본다.
- `docker volume ls`에 64자리 해시 이름의 볼륨이 보이면 **익명 볼륨**이다. 다른 프로젝트가 쓰는 볼륨일 수 있으니 `prune` 전에 목록을 확인한다.

### `-v`의 앞부분이 뜻하는 것

| `-v` 형태 | 종류 | 설명 |
|-----------|------|------|
| `-v users-data:/app/data` | **네임드 볼륨** | 경로가 아닌 이름. 같은 이름의 볼륨이 없으면 도커가 **자동으로 생성**한다. |
| `-v /Users/me/data:/app/data` | **바인드 마운트** | 호스트의 지정 폴더를 그대로 연결한다. |
| `-v /app/data` | **익명 볼륨** | 앞부분 없이 컨테이너 경로만. 해시 이름이 붙는다. |

`docker volume create`를 따로 하지 않아도 `-v users-data:...`로 처음 실행하는 순간 볼륨이 만들어진다. **이름이 곧 어떤 볼륨인지를 결정**하므로 이름을 바꾸면(`users-data2`) 새 빈 볼륨이 연결되어 기존 데이터가 보이지 않는다.

## 정리

```bash
docker rm -f docker-practice-app
docker volume rm users-data    # 사용 중인 볼륨은 삭제되지 않는다
```

## 참고

- `docker run -d` 직후 바로 `curl`을 호출하면 서버가 아직 뜨는 중이라 `Connection reset by peer`가 날 수 있다. 1~2초 뒤에 다시 시도한다.
- 실습 서버는 파일 락 없이 JSON 파일에 쓰므로 동시 요청이 많은 환경에는 맞지 않는다. 실서비스에서는 DB를 쓴다.
