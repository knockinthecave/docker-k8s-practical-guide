# 볼륨 관리하기

> [03.Understanding Volumes](./03.Understanding%20Volumes.md)에서 정리한 볼륨·바인드 마운트를 읽기 전용으로 제한하고, `docker volume` 명령으로 조회·삭제하는 방법을 다룬다.

## 바인드 마운트를 읽기 전용으로

바인드 마운트를 쓰면 호스트에서 바꾼 내용이 컨테이너 내부에 **바로 반영**된다. 파일을 수정하는 쪽은 **호스트 머신**이어야 하고, 컨테이너가 마운트된 소스를 바꿀 수 있어서는 안 된다.

이때 바인드 마운트를 **읽기 전용(read-only)** 으로 만든다. 컨테이너 내부 경로 뒤에 `:ro`를 붙인다.

```bash
docker run -d -p 8000:8000 --name docker-practice-app \
  -v /Users/me/project:/app:ro \
  docker-practice-image
```

- `/app`과 그 하위 폴더 전체에 컨테이너가 **쓸 수 없다.**
- 호스트에서의 수정은 그대로 컨테이너에 반영된다.

### 하위 경로에 쓰기가 필요한 경우

`/app`보다 **더 긴 내부 경로**에 별도 볼륨을 마운트하면 그 경로는 다시 쓸 수 있다. 도커는 경로가 충돌하면 더 구체적인 경로를 우선하기 때문이다. (익명 볼륨으로 `node_modules`를 지키던 것과 같은 원리)

```bash
docker run -d -p 8000:8000 --name docker-practice-app \
  -v /Users/me/project:/app:ro \
  -v users-data:/app/data \
  -v /app/tmp \
  docker-practice-image
```

| 경로 | 쓰기 |
|------|------|
| `/app` (바인드 마운트, `:ro`) | 불가 |
| `/app/data` (네임드 볼륨) | **가능** |
| `/app/tmp` (익명 볼륨) | **가능** |

## 볼륨은 도커가 관리한다

- 볼륨은 도커가 관리하며, 호스트 어딘가에 폴더를 **자동으로 생성**한다.
- 컨테이너를 실행할 때 해당 볼륨이 없으면 도커가 만든다.
- `docker volume` 명령으로 도커가 실제로 만든 것을 들여다볼 수 있다.

## 볼륨 조회: `docker volume ls`

```bash
docker volume ls
```

- 도커가 관리하는 **볼륨 전체**를 보여준다.
- **바인드 마운트는 도커가 관리하지 않으므로 목록에 나오지 않는다.**

### 직접 생성

보통은 `-v`로 처음 실행할 때 자동 생성되지만, 미리 만들 수도 있다.

```bash
docker volume create feedback-files
docker volume ls
```

이후 `-v feedback-files:/app/feedback`로 실행하면 **이미 있는 볼륨을 사용**하고, 없으면 자동으로 생성한다.

## 볼륨 상세 정보: `docker volume inspect`

```bash
docker volume inspect <VOLUME_NAME>
```

이름, 드라이버, 생성 시각, 옵션 등 볼륨 정보를 볼 수 있다.

- `Mountpoint`는 호스트 머신이 아닌 **Docker VM 내부의 마운트 경로**다. (Docker Desktop 기준, Finder로 열리지 않는다)
- `Options`는 볼륨 **드라이버 옵션**이다. `:ro` 여부는 볼륨이 아니라 컨테이너의 마운트 설정이므로 여기서 확인되지 않는다. 컨테이너 쪽에서 본다.

```bash
docker inspect -f '{{json .Mounts}}' docker-practice-app   # "RW": false 면 읽기 전용
```

## 볼륨 삭제

### 개별 삭제: `docker volume rm`

```bash
docker volume rm <VOLUME_NAME>
```

- **사용 중인 볼륨은 삭제할 수 없다.** 먼저 해당 컨테이너를 중지하고 삭제해야 한다.
- 볼륨을 지우면 앱이 만든 **모든 파일이 함께 삭제**된다. 같은 이름으로 다시 만들어도 **복구되지 않는다.**

```bash
docker rm -f docker-practice-app
docker volume rm users-data
```

### 일괄 삭제: `docker volume prune`

```bash
docker volume prune
```

- 어떤 컨테이너에도 연결되지 않은 볼륨을 한 번에 지운다. 실행 중인 컨테이너가 쓰는 볼륨은 제외된다.
- 컨테이너를 삭제한 뒤 남은 **네임드 볼륨도 대상**이 될 수 있다. 실행 전에 `docker volume ls`로 목록을 확인한다.

## 정리

| 명령 | 용도 |
|------|------|
| `-v 호스트경로:/경로:ro` | 바인드 마운트를 읽기 전용으로 |
| `docker volume ls` | 도커가 관리하는 볼륨 목록 (바인드 마운트 제외) |
| `docker volume create 이름` | 볼륨 미리 생성 |
| `docker volume inspect 이름` | 볼륨 상세 정보 (`Mountpoint`는 VM 내부 경로) |
| `docker volume rm 이름` | 볼륨 삭제 (사용 중이면 불가, 복구 불가) |
| `docker volume prune` | 미사용 볼륨 일괄 삭제 |
