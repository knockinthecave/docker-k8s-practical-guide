# 데이터 이해하기: 이미지·컨테이너의 데이터 종류

> 어플리케이션이 다루는 데이터는 성격에 따라 **세 가지**로 나뉜다. 어디에 저장되고, 컨테이너가 사라질 때 어떻게 되는지가 각각 다르다.

## 어플리케이션 구성

어플리케이션은 **소스 코드**와 그것이 실행되는 **환경**으로 이루어진다. 코드는 우리가 직접 작성한 것이다.

이 코드와 전체 환경이 **이미지**에 추가되어 빌드되고, 이미지를 기반으로 **컨테이너**에서 실행된다.

## 데이터의 세 종류

| 종류 | 예시 | 저장 위치 | 특징 |
|------|------|-----------|------|
| 1. 어플리케이션 (코드 + 환경) | 소스 코드, 의존성 | **이미지** | 읽기 전용, 고정됨 |
| 2. 임시 어플리케이션 데이터 | 실행 중 생긴 임시 데이터 | **컨테이너** (read-write 레이어) | 컨테이너와 함께 사라져도 괜찮음 |
| 3. 영구 어플리케이션 데이터 | 사용자 계정 등 | **컨테이너 + 볼륨** | 컨테이너가 사라져도 유지되어야 함 |

## 1. 어플리케이션 (코드 + 환경)

- 코드와 환경은 이미지로 **복사**되므로 그 시점에 **고정**된다.
- 데이터·소스 코드 등 이미지에 복사된 것은 더 이상 변경할 수 없다. **이미지는 읽기 전용**이기 때문이다.
- 따라서 실행 중인 어플리케이션이 자기 코드를 수정해서는 안 된다.
- 코드를 바꾸려면 이미지를 **다시 빌드**한다.

## 2. 임시 어플리케이션 데이터

어플리케이션이 **실행되는 동안 생기는 데이터**다.

- 장기간 보관할 데이터가 아니다.
- 실제로 쓰기는 하지만 **일시적**이고, 없어져도 괜찮다.
- 이미지가 아닌 **컨테이너**에 저장된다.

### 컨테이너 레이어(read-write 레이어)

컨테이너는 이미지 위에 얹힌 **부가 레이어**를 갖는다. 이 레이어는 이미지를 인식하고 이미지의 파일 시스템을 미러링한다.

- 도커는 이 레이어를 통해 **read-write 권한**으로 파일 시스템을 조작한다.
- 이미지 자체는 변경하지 않고, **부가 레이어에서만** 변경한다.
- 도커는 컨테이너의 변경 사항을 추적한다. 이미지의 파일 시스템을 가져와 read-write 레이어에 저장된 변경 사항과 결합해 **최종 파일 시스템**을 만든다.

```
┌────────────────────────────────┐
│ 컨테이너 레이어 (read-write)     │ ← 변경 사항이 여기에만 저장됨
├────────────────────────────────┤
│ 이미지 레이어 (read-only)        │ ← 코드 + 환경, 변경 불가
└────────────────────────────────┘
```

컨테이너에 저장하라고 하면 파일이 무엇이든 read-write 레이어에 저장된다. 즉 **컨테이너 안에만** 있고, 로컬 머신에도 이미지에도 존재하지 않는다.

## 3. 영구 어플리케이션 데이터

**사용자 계정**처럼 계속 유지되어야 하는 데이터다. 실행 중인 컨테이너에서 만들어지지만, 컨테이너가 사라져도 남아 있어야 한다.

- 컨테이너를 **중지했다가 다시 시작**해도 데이터가 그대로 보존되어야 한다.
- 컨테이너를 중지하고 **새 버전을 배포**할 때도 유실이 없어야 한다.
- read-write 데이터라는 점은 임시 데이터와 같지만, **영구적으로 저장**되어야 한다.
- 컨테이너에 저장하되 **볼륨(Volume)**의 도움을 받는다.

## 핵심 정리

- 이미지 = 읽기 전용 (코드·환경). 실행 중 수정하지 않는다.
- 컨테이너 read-write 레이어 = 임시 데이터. 컨테이너가 제거되면 함께 사라진다.
- **볼륨 = 컨테이너가 종료·삭제되어도 유지해야 하는 영구 데이터를 위한 도커의 핵심 개념.**
