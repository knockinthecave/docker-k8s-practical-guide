# 데이터 관리 요약

> 이 챕터에서 다룬 이미지·컨테이너의 데이터 관리를 정리한다. 자세한 내용은 [01.Understanding Data](./01.Understanding%20Data.md)부터 [06.ARGuments & ENVironment Variables](./06.ARGuments%20%26%20ENVironment%20Variables.md)까지 참고.

## 핵심 흐름

1. **이미지는 읽기 전용**이다. 컨테이너는 그 위에 **read-write 레이어**를 추가해 데이터를 읽고 쓴다.
2. 하지만 컨테이너를 제거하면 그 레이어에 기록한 데이터도 **함께 사라진다.**
3. 모든 어플리케이션에는 컨테이너가 사라져도 **살아남아야 할 데이터**가 있다. 그래서 **볼륨**을 쓴다.
4. 개발 중에는 소스 코드를 바로 반영하고 싶다. 이럴 때 **바인드 마운트**를 쓴다.

## 볼륨

- 호스트 머신에 있는 폴더이며, 도커가 관리하고 컨테이너에 **마운트**된다.
- 컨테이너 내부의 매핑된 경로에 기록한 내용은 **호스트 머신에도 저장**된다.
- 이 데이터는 컨테이너가 제거되어도 남는다. 컨테이너 안에만 저장되는 것이 아니다.
- `COPY`처럼 한 번 복사하고 끝나는 것이 아니라, 컨테이너 폴더와 호스트 폴더가 **계속 연결**된 상태다.

## 세 가지 종류

| | 익명 볼륨 | 네임드 볼륨 | 바인드 마운트 |
|---|-----------|-------------|---------------|
| 선언 | Dockerfile `VOLUME` / `-v /경로` | `-v 이름:/경로` | `-v 호스트절대경로:/경로` |
| 호스트 경로 | 도커 관리 (모름) | 도커 관리 (모름) | **직접 지정 (앎)** |
| 컨테이너 제거 후 | `--rm`이면 함께 삭제 | **유지** | 유지 (호스트 폴더이므로) |
| 컨테이너 간 공유 | 불가 | 가능 | 가능 |
| 직접 편집 | 불가 | 사실상 불가 | **가능** |
| 주 용도 | 특정 경로 보호, 컨테이너 효율 | **영구 데이터** | **개발 중 소스 코드 반영** |

### 익명 볼륨

- 컨테이너에 종속된다. `--rm`으로 실행한 컨테이너를 제거하면 함께 삭제된다.
  - `--rm` 없이 실행했다면 컨테이너를 지워도 볼륨은 남는다. 다만 새로 `docker run`하면 **새 익명 볼륨**이 만들어져 이어 쓸 수 없다.
- 그래서 **지속 데이터에는 적합하지 않다.**
- 대신 컨테이너를 효율적으로 운용할 때 유용하다. 대표적으로 바인드 마운트가 덮어쓰지 못하게 **특정 하위 경로를 보호**한다. (예: `node_modules`)

### 네임드 볼륨

- 컨테이너를 제거해도 **살아남는다.** 영구 저장이 가능하다.
- `docker run -v 이름:/경로`로 만든다. Dockerfile 안에서는 만들 수 없다.
- 같은 이름의 볼륨이 없으면 **새로 만들고**, 있으면 **기존 것을 그대로 쓴다.**

### 바인드 마운트

- 호스트 머신의 **로컬 폴더를 직접 매핑**한다. 개발자가 소스 코드를 컨테이너에 그대로 노출할 수 있다.
- 미러링되는 호스트 경로를 알고 있으므로, 그 경로에서 데이터를 바꾸면 컨테이너가 **항상 최신 데이터**를 쓴다.
- 호스트 내용이 컨테이너 경로를 **덮어쓰므로**, 지켜야 할 하위 경로는 **익명 볼륨**을 함께 지정한다.
  - 경로가 충돌하면 도커는 더 길고 구체적인 경로를 우선한다.
- 호스트 폴더를 읽기 전용으로 두려면 `:ro`를 붙인다. ([04.Managing Volumes](./04.Managing%20Volumes.md) 참고)

## 설정 방법

`docker run -v`로 설정한다. 앞부분이 무엇인지에 따라 종류가 정해진다.

| 쓰는 값 | 예시 | 종류 |
|---------|------|------|
| 컨테이너 경로만 | `-v /app/tmp` | 익명 볼륨 |
| 이름 | `-v users-data:/app/data` | 네임드 볼륨 |
| 호스트 절대 경로 | `-v /Users/me/project:/app` | 바인드 마운트 |

```bash
docker run -d -p 8000:8000 --name docker-practice-app \
  -v users-data:/app/data \
  -v /Users/me/project:/app \
  -v /app/tmp \
  docker-practice-image
```

위 예시는 네임드 볼륨(`users-data`), 바인드 마운트(`/Users/me/project`), 덮어쓰기를 막는 익명 볼륨(`/app/tmp`)을 한꺼번에 쓴 경우다.

## 이미지에 넣지 않을 것: `.dockerignore`

- `COPY`로 이미지에 복사하면 안 되는 파일·폴더(`.git`, `.venv`, `.env` 등)를 `.dockerignore`에 적는다.
- 비밀 값이 이미지에 섞이는 것을 막고, 빌드 컨텍스트 전송량도 줄여 준다.

## 하드코딩 없이: ARG와 ENV

- **빌드 인수(ARG)**: `docker build --build-arg`로 빌드 시점에 값을 바꾼다. Dockerfile 안에서만 쓸 수 있다.
- **런타임 환경변수(ENV)**: `docker run -e` / `--env-file`로 실행 시점에 값을 바꾼다. 앱 코드에서도 읽을 수 있다.
- 둘을 쓰면 포트, 버전 표기처럼 바뀌는 값을 **하드코딩하지 않고** Dockerfile을 관리할 수 있다.
- 비밀 값은 Dockerfile의 `ENV`에 넣지 말고 `--env-file`로 런타임에만 전달한다. (`docker history`로 노출될 수 있다)
